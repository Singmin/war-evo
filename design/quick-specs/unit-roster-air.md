## 2. 步骤 A：按价格排序

现有编号和价格（`UNIT_BASE`）：0 步兵 15 / 1 射手 25 / 2 骑兵 40 / 3 重装 100 / 4 炮兵 70。

**不要改兵种编号。** 编号被克制环（`BEATS`、`BEATEN_BY`）、科技加成（`m.hp[3]` 这类写法）、美术表（`ERA_ART`、`SPRITE_META`）到处引用。

做法：

- 在 `js/core/data.js` 加一个显示顺序常量，例如 `const UNIT_ORDER = [0, 1, 2, 4, 5, 3];`（步骤 A 阶段先写 `[0, 1, 2, 4, 3]`）。
- `js/ui/bar.js` 第 30 行的 `for (let t = 0; t < 5; t++)` 改成按 `UNIT_ORDER` 遍历。按钮 id 仍然是 `'u' + 兵种编号`，不要改成位置序号（`refreshMenu` 用 `/^u(\d)$/` 取编号去拿图标）。
- 键盘快捷键 `1`–`5`（在 `js/input.js`，本文档作者没读过这个文件）要跟着按钮位置走：按 `1` 是最左边的按钮。加空军后是 `1`–`6`。
- `README.md` 操作表里"出步兵 / 射手 / 骑兵 / 重装 / 炮兵"那一行同步改。

所有时代的价格都是 `基础价 × 1.7^第几个时代`，降价科技也是整体打折，所以这个顺序在任何时代、任何科技下都成立，不需要动态排序。

## 3. 步骤 B：空军

### 3.1 规则

| 规则 | 内容 |
|---|---|
| 飞行 | 不占地面位置。不被任何地面兵挡住，也不挡地面兵。和敌方空军互相穿过。 |
| 己方空军之间 | 照常排队，保持 `SPACING` 间距（不叠在一起）。 |
| 谁能打空军 | 射手（编号 1）、防御塔、大招。 |
| 谁打不到空军 | 步兵、骑兵、重装（近战）；炮兵（范围伤害只炸地面）；空军自己。 |
| 空军打谁 | 敌方最前排的**地面**兵；前方没有地面兵时打基地。 |
| 不能绕后 | 敌方最前排地面兵进入射程就停下来打，不会越过它飞向基地。 |
| 打基地 | 伤害 × `AIR_BASE_DMG`（0.5）。 |
| 克制 | 原来的五兵克制环不动。射手打空军 ×1.6。空军不克制任何兵种。 |
| 人口 | 计入 `MAX_UNITS`（20）。出生检查只看己方空军，不被门口的地面兵堵住。 |
| 主场减伤、回血、击杀奖励 | 和其他兵一样，不做特殊处理。 |

### 3.2 数值（估算，待验算）

加到 `UNIT_BASE` 末尾：

```js
{ price: 85, hp: 70, atk: 16, range: 120, rate: 1.2, speed: 110, train: 3.5, w: 34, h: 30, ranged: true, air: true },   // 空军
```

新常量：

```js
const AIR_ALT = 150;        // 空军离地高度（世界像素），只影响画面和弹道起止点
const AIR_BASE_DMG = 0.5;   // 空军打基地的伤害倍数
```

价格顺序：步 15 → 射 25 → 骑 40 → 炮 70 → 空 85 → 重 100。

已知风险：对面没有射手也没有塔时，空军不会受伤。靠三样东西兜底——射手便宜（25）、AI 会补射手（3.5 节）、大招能打到空军。实现后要专门试这种局面。

### 3.4 逐文件改动

#### `js/core/data.js`

- `UNIT_BASE`、`UNIT_NAMES`、`TYPE_SHORT`、`TYPE_DESC`：见上。
- `ERA_ART`：每行加第 6 个数（矢量兜底画法编号，填该行第 2 个数即可）。
- `mkMod()`：`hp`、`atk`、`range`、`speed` 四个数组从 5 个 `1` 改成 6 个。
- 所有 `for (let i = 0; i < 5; i++)` 遍历兵种的地方改成 `< UNIT_BASE.length`。在 `ERA_BONUS[15]`，以及 `PERKS` 里的 `march`、`omni`、`rage`、`conquest`。漏改的后果是"所有兵 +X%"的科技对空军无效。
- `BEATS` 改成 `[2, 0, 4, 1, 3, -1]`，`BEATEN_BY` 改成 `[1, 3, 0, 4, 2, 1]`。
- `counterMult`：`BEATS` 一个兵种只能填一个克制对象，射手克步兵已经占了。加一个条件：

```js
function counterMult(att, def) {
  return att >= 0 && (BEATS[att] === def || (att === 1 && def === 5)) ? COUNTER_BONUS : 1;
}
```

- `unitStats`：返回值里加 `air: !!b.air`。
- `PROJ_STYLE`、`projStyle` **不用改**：空军的子弹会自动用同时代射手的外观（`projStyle` 只区分"炮兵"和"其他"）。

#### `js/core/sim.js`

- `trySpawn`：
  - 单位对象加 `air: st.air`。
  - 出生点阻挡检查（`block`、`SPAWN_STACK` 那几行）只和**同一层**的己方兵比：空军只看空军，地面只看地面。
  - 人口上限 `MAX_UNITS` 仍然两层合计。
- `stepUnits` / `moveLine`：现在每方一条按 x 排序的队列，"敌方第一个活着的"就是目标。改成每方两条：地面、空中。
  - 地面兵：目标是敌方地面最前排。**射手例外**：在"敌方地面最前排"和"敌方空中最前排"里选边缘距离更近的那个。
  - 地面兵的前进距离只受敌方**地面**最前排限制（`Math.min(..., eDist, ...)` 里的 `eDist` 用地面的）。空军不挡路。射手射程内有空军时会停下来打，这是预期行为。
  - 空军：目标只能是敌方地面最前排；队内间距只和己方空军比。
  - 炮兵、近战兵完全不看空军。
- `attackBase`：攻击者是空军时伤害 × `AIR_BASE_DMG`。
- `stepProjs` 的范围伤害循环：`p.splash` 且**不是塔打的**（`!p.tower`）时跳过 `u.air`。重塔的范围伤害可以打到空军。
- `stepProjs` 的单体改目标（`nearestFoe`）：统一用 `canTargetUnit` 检查权限，只有射手或塔可以改目标为空军。弹丸只保存基础伤害，在命中时对实际目标计算一次克制；原实现发射和命中各乘一次，已修正。
- 高度：加一个 `const unitAlt = u => u.air ? AIR_ALT : 0;`（放 `data.js` 或 `sim.js` 开头）。离地 y 向上为负，下面这些地方要**减去**它：
  - `attackUnit` / `attackBase` 里 `shoot` 的起点 `-u.h * 0.65`。
  - `projPos` 里目标的 `ty`。
  - `stepProjs` 里命中特效的 y。
  - `stepTowers` 里的 `t.aim`。
  - `damageUnit` 里死亡特效和飘字的 y。
- `stepShells`（大招）：不用改，大招照常打空军。

#### `js/core/ai.js`

- `aiPickUnit`：
  - `Math.floor(Math.random() * 5)` 改成 `* UNIT_BASE.length`。
  - `cnt = [0, 0, 0, 0, 0]` 改成 6 个。困难难度的加权逻辑靠 `BEATEN_BY[5] = 1` 自动会出射手。
  - 在 `smart` 分支最前面加一条：敌方存活空军数 > 我方存活射手数＋队列射手数时，70% 概率直接出射手。
  - 最后那个补位分支（`front <= back ? ... : ...`）里加：敌方射手 ≤ 1 个且没有防御塔时，15% 概率出空军。
- `aiNextEra`：`cnt` 改成 6 个；空军算进 `ranged`。

#### `js/ui/bar.js`

- 兵种按钮遍历 `UNIT_ORDER`（步骤 A 已改），加空军后是 6 个按钮加"返回"共 7 个。现在根菜单是 6 个按钮，**要在手机横屏宽度下确认 7 个放得下**，放不下就缩小按钮或把"返回"换成图标。

#### `js/ui/hud.js`

## 4. 步骤 C：美术

- 生成器是 `tools/gen_sprites.py`，每个时代一个 `tools/sprite_era<N>.py`，各画 5 个兵种。产物是 `assets/sprites/era<N>.webp` 和 `js/render/sprite_meta.js`（生成文件，不要手改）。
- 每个兵种 12 帧：走 0–3、攻击 4–7、死亡 8–11；三行：我方、敌方、纯白。空军的"走"是飞行循环，"死亡"是坠落。
- 需要在 17 个 `sprite_era<N>.py` 里各加第 6 个兵种，然后运行 `python tools/gen_sprites.py`。
- 步骤 B 阶段的占位办法：`spriteMeta(era, 5)` 为空时走 `world.js` 的矢量兜底画法，先画一个带翅膀的简单形状。不要去手改 `sprite_meta.js`。

## 8. 试玩反馈修正：敌人出空军与灵活搭配（2026-11-10）

### 原因

- 原方案把空军放在选兵兜底分支，且要求玩家没有任何塔、射手不多于 1 个。玩家只要造一座塔，普通／困难 AI 的空军概率就变成 0。
- 有敌方前排时，普通 AI 要先错过 60% 的克制分支；困难 AI 还要先错过 85% 的加权克制分支。即使满足条件，空军实际概率也只有约 6%／0.9%，而不是直观理解的 15%。
- 选中的贵兵买不起时立即改买射手或步兵，导致金币长期被便宜兵耗掉，难以训练空军、重装和炮兵。
- 原来的前后排补位没有计入全部训练队列，且固定长队列会延迟应变。`emergency` 原本只提高存钱期间的出兵预算，没有真正取消攒钱限制。

### 实现

- 六兵种始终共同参与加权选择；按敌军阵容、己方前排／后排缺口、已训练及在训兵种数量改变选择倾向。对方防空多会降低空军权重，塔不再彻底禁用空军。
- 骑兵、重装、炮兵和空军都可正常被选中；已有或正在训练的同类越多，重复补该兵种的倾向越低。
- 安全且已有一定兵力时，允许为选定兵种留金币；保持计划直到买得起、计划过期、时代变化或受到威胁。无兵开局只考虑短等待内买得起的单位。
- 敌人逼近时，停止为买不起的贵兵等待。缺对空时优先补射手，缺地面前排时优先补步兵；紧急情况下暂停攒跃迁钱，优先救场。
- 常规训练队列目标为 2 个，紧急／攒钱时为 1 个；困难 AI 遇到对方跃迁，仍能增加队列施压。已付费队列照常完成，没有取消或退款机制。
- 三难度的基础权重、克制倾向、重复抑制与等待参数集中在 `js/core/data.js` 的 `AI_RECRUIT`；逻辑在 `js/core/ai.js`。兵种数值、对空权限和经济收益不变。
- 修改前备份：`production/backups/ai-recruitment-20261110-125909/`。

### 验证与限制

- 54 项针对性检查通过：包括三难度×0／1／3 座敌塔的选兵分布、反制偏好、队列覆盖、实际收入攒钱、空军训练、紧急打断、跃迁让位、17 个时代的价格，以及 6 场付费模拟对局。
- 固定场景（己方可支配 1000 金、对方一名步兵、己方暂无兵）各采样 10000 次：普通／困难 AI 面对一座塔仍约有 11.58%／11.34% 的选择为空军。该数字仅描述此场景，不是所有对局的固定概率。
- 独立 Chromium 浏览器中，三难度都在真实训练队列完成后部署空军；首支空军出现于简单 45.9 秒、普通 21.1 秒、困难 34.53 秒，随后各自完整对局正常结算。测试使用可重复的随机序列和自动玩家操作，不代表保证每局在这些时间出空军。
- 另验困难 AI 在敌方空军逼近时，放弃买不起的重装计划，用 90 金中的 25 金购买射手；未获得额外金币。
- 浏览器没有页面异常。未做真人长时间试玩，也未保证每局都出空军；对方防空和近基地压力很大时，地面反制兵仍可能更合理。
- 新策略改善选择与应变，不代表第 7 节的长局僵持已解决；正式平衡仍需单独评估。

## 10. 空军对空军、敌人被堵门的应对（2026-11-11）

试玩反馈：空军遇到敌方空军不会打；我方堵到敌方门口后，敌人只会出步兵。

### 规则变更

- 空军可以攻击敌方空军。能对空的来源现在是：射手、空军、防御塔、大招。近战、骑兵、重装、炮兵仍然打不到空军。
- 这取代了第 3.1 节和第 5 节里"空军不能对空""双方空军相遇时互相穿过"两条：双方空军进入射程后会停下对射，不再穿过。空军打空军没有克制加成，射手打空军仍是 1.6 倍。
- 射手和空军选空中目标时取实际距离最近的一架。
- 兵种数值没有改。

### 敌人被堵门

原因：被压到门口时，原逻辑只在"当前买得起"的兵里选，而且门口没有前排就必定补步兵，收入被一个个步兵耗光，永远攒不出别的兵和塔。

- 被堵门时保留购买计划，可以为克制兵种攒 `siegeWait` 秒的钱；门口没有前排时每 `blockEvery` 秒才补一个步兵顶住。
- 选兵时降低"正好被门口敌兵克制"的兵种的权重。
- 被堵门且有空塔位时优先补塔：买得起中塔直接建，一座塔都没有时先建轻塔，差一点钱时最多停 `towerWait` 秒出兵去攒。只对普通和困难生效。
- 对方空军多于我方能对空的兵时，射手和空军的权重都会提高；己方空军也算对空力量。
- 参数在 `js/core/data.js` 的 `AI_RECRUIT`，逻辑在 `js/core/ai.js`。修改前备份：`production/backups/air-vs-air-siege-20261111/`。

### 验证与限制

- 浏览器规则检查通过：空军互相造成伤害并停在射程内，地面兵和炮兵仍打不到空军，射手能打，打基地伤害减半；34 个时代／外观组合、桌面点击和 812×375 触屏出兵无异常。
- 固定堵门场景（我方一支部队钉在敌方门口，每 12 秒补一个兵，120 秒，每组 16 局，普通和困难各 6 组）：改前"地面＋空军混编"和"空军为主"两类堵门，敌方基地 16 局里失守 4–12 局；改后 12 组全部没有失守，每局都建了塔。纯地面堵门改前改后都守得住。
- 该场景下敌人购买的兵种比例变化不大：纯地面堵门时步兵占 52–56%（改前 53–58%），混编和空军堵门时占 37–48%（改前 38–46%），其余是射手、骑兵、炮兵、少量空军和重装。步兵挡门本身划算，没有硬压比例；守住与否的差别主要来自补塔。
- 该场景里的"我方"是固定脚本，没有塔、大招和正常经济，敌人守住后经常直接反推获胜，这不代表真人对局的胜率。
- 完整对局模拟（我方用同一套电脑逻辑并加 80% 收入，每难度 10 局）：1500 秒内未分胜负的局数，普通 2→3、困难 2→4。长局僵持的遗留问题没有解决，可能略有加重，需要真人试玩判断。
- 证据：`production/qa/evidence/air-duel-siege/`。
